# 北京故宫雪景水晶球：从运行到修改

这是使用 Three.js r169 制作的故宫意象幻想微缩场景，包含宫殿、院落、空中楼阁、玻璃壳、风雪及灯光。建筑与空间经过艺术化组合，不是故宫测绘复原。

![实际运行截图](screenshots/forbidden-city-globe.png)

## 1. 先运行成品

在仓库点击 Code → Download ZIP，解压后使用支持 WebGL 2 的现代浏览器打开根目录 `北京故宫雪景水晶球.html`。Three.js 与 OrbitControls 已内联，不需要 npm、模型下载或 CDN。GitHub 的文件详情页只显示源码，不直接运行场景。

也可以在解压目录运行 `python -m http.server 8000`，访问 `http://localhost:8000/`，选择 HTML 文件。该方式需要已有 Python。

- 左键拖拽：旋转；滚轮：缩放；右键拖拽：平移。
- 点击底座正面的“起风”：扬起积雪；连点可以叠加阵风，长按再释放会增加力度。
- 在球壳上拖动：相机旋转的同时给雪花施加有上限的扰动；点击球壳可看到局部涟漪。

## 2. 读源码时先跳过内联库

文件前半部是 Three.js 与 OrbitControls 的库代码。建议用编辑器搜索下面的唯一标识，定位场景代码，不要直接修改库内部。

## 3. 建筑：先搭轮廓，再加细节

台基和门板用盒状部件，柱子用圆柱，曲线构件用管状几何。屋顶用网格函数控制高度：中部形成屋脊，边缘再抬高，构成可辨识的翘檐。随后按间距重复门窗、栏杆和灯笼。场景用分组管理组件，静态部分合并以减少绘制开销。

初次练习只保留“台基 + 柱子 + 一层屋顶”的目标，不要第一步就追求全部装饰。模型位置或屋顶形状改变后，要同步修改碰撞表面；视觉网格和雪花碰撞数据不是同一份对象。

## 4. 玻璃：先有场景，再取样折射

本作玻璃使用 `ShaderMaterial`。先把场景颜色和深度渲染到离屏目标，再绘制球壳。着色器依据外壳与内壳交点计算折射方向，沿射线检查屏幕空间深度，找到可采样的场景位置。环境反射与随视角变化的菲涅耳权重让球边缘更明显。

这是适合实时效果的屏幕空间近似，并非完整离线路径追踪。屏幕外信息与遮挡会限制可获得的折射内容。不要把普通 `opacity` 调低当作本项目的完整玻璃实现。

修改练习：备份 HTML，搜索 `uThickness:{value:.145}`，先试 `.10`，再试 `.20`。每次刷新并从正面、斜侧面检查宫殿轮廓。这里的数值是场景单位，不是毫米。折射率 `1.48` 在着色器多个介质交界计算中配套使用，初学者先不要只改单处。

## 5. 雪：位置、速度、旋转和接触状态

8200 片雪晶分为八类：六枝树枝晶、六角薄板晶、蕨枝星晶、针状晶束、短柱冰晶、松软团絮、不规则碎冰、细雪粉。每类设置不同尺寸、重力、阻力与附着参数。

`snowStep` 更新风场、速度与位置，并处理球边界、屋顶、地面、建筑简化碰撞体和空中结构表面。碰撞后按条件滑动、反弹或停留；再次起风会唤醒已有积雪。它是为作品设计的近似模拟，不等同于气象科学模型。

雪晶按形态使用实例化缓冲几何及属性批量绘制，位置、外观、四元数旋转等逐帧更新；本作不是给每片雪分别创建一个普通 Mesh，也不是简单的二维点精灵。

修改练习：把 `const snowCount=8200` 改为 `const snowCount=3000`，重新打开作品，比较密度和设备响应。粒子按索引分配类别，修改数量仍会保留八类。运行状态以实际粒子数量为准，部分说明字符串仍写着 8200，若要发布修改版也应同步更新说明。

## 6. 起风：从点击到模拟

按钮通过 `Raycaster` 检测命中。按下时临时禁用相机控制；释放时确认仍命中按钮、移动距离足够小，再调用 `stirGlobeSnow`。长按时计算力度，连击可叠加阵风。风场逐渐衰减后，雪重新沉降。

球体拖动另行计算相机相对方向的扰动，且限制强度。把“按钮点击”和“相机拖拽”分开处理，能避免点按钮时整颗球跟着转。

## 7. 时间步长与性能

当前 `updateSnow` 按真实帧间隔推进，每帧最多处理 0.08 秒并拆成最多两个不大于 0.04 秒的子步。长时间卡顿时会截断时间，不能声称任何设备都完全同步。帧率取决于 GPU、分辨率、视角及场景负载。

静止相机下，部分折射输入每四帧更新，反射每六帧更新；相机变化时及时更新。主画面中的雪晶仍逐帧绘制。减少离屏重复绘制比盲目删掉所有细节更值得先检查。

## 8. 用已有审计接口验证修改

打开浏览器开发者工具 Console，输入：

```js
const globe = window.__forbiddenCityGlobe;
globe.audit();
globe.auditSnowInteraction();
```

`audit()` 检查粒子非有限值、球体越界、部分简化实体穿入及运行错误；`auditSnowInteraction()` 返回按钮次数、阵风、上扬数量、停留数量及类别分布。这些指标有覆盖范围限制，不能代替所有几何接触和所有视角的目视检查。

本次上传前在桌面 Edge 中实际打开源文件并点击“起风”两次：8200 个粒子，采样时 invalid / outside / belowSurface 均为 0，无页面与控制台错误，按钮计数为 2。测试记录见 `verification/forbidden-city.json`。这是一次桌面检查，不是所有手机性能承诺。

## 9. 从空白开始的制作顺序

1. 先搭相机、灯光、一个方块和 OrbitControls，确认能显示与旋转。
2. 替换成简化宫殿，先看比例、屋顶轮廓和正背面。
3. 添加玻璃壳与离屏场景采样，分别检查清晰度、边缘反射和遮挡。
4. 先放少量雪晶，做重力和停止，再加风场、旋转与更多碰撞体。
5. 加入起风按钮，验证点击不会误触相机。
6. 最后增加细节、灯光、水面和粒子密度；每一步都留一个可运行版本。

可用的分步需求模板：“基于当前 HTML，只完善【一个模块】；保留【已通过的结构与交互】；用【指定视角和操作】检查，交付可运行文件与修改说明。”这是复现用模板，不是本作品历史制作记录。
